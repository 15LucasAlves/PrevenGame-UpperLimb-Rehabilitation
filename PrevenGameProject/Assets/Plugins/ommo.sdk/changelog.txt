# Changelog

## [0.22.0] - 2026-02-27
### Breaking Changes
- For firmware > 7014, requesting base station data will no longer start the motor automatically

### New Features
- Added a reference device state stream API for receiving updates on reference mode
- Quick connect support is added for devices that have been previously connected during this execution run
- Sync and data channels are now shown at the top level for hardware on the user interface
- Base station data can be requested without starting the motor
- Added SDK Received latency timestamp to data packets
- Added ability to request latest data within a specified time frame
- (SDK) Added a string conversion for Latency Timestamp Types
- (App) Added latency timestamps to output logs
- (App) Added crash reporting


### Bug Fixes
- (SDK) Fixed a possible crash when using WirelessManager
- (SDK) Fixed a possible crash in the device event stream API
- Prevent a possible crash during the shutdown process
- Prevent a crash that can happen if the base station sync channel has not been set
- Reference mode can no longer be set for a device without a magnetometer
- System wide time is no longer toggled repeatedly during execution
- Correctly display device images when a msiu is missing information
- Correctly display certain device images based on device part numbers
- USB threads are now prioritized to help reduce latency in cases of thrashing
- (App) Devices with an empty or invalid pose are no longer displayed
- (App) Fixed issue where text could be displayed at the incorrect location

## Other
- [Algorithm] Updated the algorithm to version 0.16.23

## [0.19.1] - 2025-01-10
## Changed
- [DEPRECATION] Minimum supported firmware version for base stations and wireless receivers is now 5003
- Fixed issue with deep scan channel selection not using the first result
- Fixed issue with port LEDs not being turned off when last sensor is removed from the SIU
- Fixed multiple data enable commands being sent for SIUs with multiple sensors
- Fixed issue causing SIUs to timeout while data is starting
- Unified tracking data handling across different data request types
- Fixed issue with wireless relay commands getting the ack queue out of sync for base stations
- Improved ACK queue handling and message clarity for specific command and ack combinations
- Included a font for standardization across platforms
- Adjusted status icon and detailed text alignment in the UI
- Fixed issue causing service to hang if grpc did not start correctly
- SIUs will now clear its error state when a new descriptor has been successfully received
- SIUs will now display an error state if no descriptor is received or no compatible sensors are connected
- Improved log message when unsupported hardware or firmware is detected
- Fixed issue that can cause log to spam and freeze the UI when unsupported or malformed data packets are received
- [BREAKING] MAG_ONLY_FUSION mode will now output the tracking unit pose instead of the calibrated tool pose
- [Algorithm] Updated algorithm to version 0.16.2 with improved motion model
- [Algorithm] Indicator value is now a distortion only indicator value

## Added
- Added handler to shutdown and flush logging properly in case of a crash or console exit
- Firmware crash logs will now be sent to sentry and cleared on the hardware
- Executable is now signed with Trusted Signing
- Base station can now start by itself without SIUs or sensors if base station data is requested
- [Algorithm] Motion indicators and bad data indicators have been split from indicator value and are now reported separately in TrackingDeviceData

## Deprecated
- Full channel scans used by FW prior to 5003 are no longer supported
